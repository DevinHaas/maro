## Current behavior and seams

- `Sources/MaroApp/HomeView.swift:115`: private `HomeVideoCard` owns hover state. Its 196-point card has a playback button covering artwork/title/creator; artwork already has a bottom-right play affordance (`:122–136`). An always-visible text Save/Saved menu follows it (`:137–143`). Place the new plus at the **card** bottom-right below/alongside metadata, outside the playback button, to avoid colliding with artwork play or creating nested buttons. Reserve its space to prevent hover layout shifts.
- `Sources/MaroApp/ApplicationModel.swift:199`: Favorites toggle reports capacity/error and calls `render()`. `:215` routes playlist saves through `pendingVideo`, expands the sidebar, and closes search. Actual presentation is a **window sheet** at `Sources/MaroApp/AppShellView.swift:28`; `AddToPlaylistSheet` (`:109`) offers a picker and separate Add confirmation. New Home control should bypass `offerAdd` and select the destination inside its anchored popover.
- `Sources/MaroApp/PlaylistLibrary.swift:206`: `add(video,to:)` validates current destination membership, then invokes existing mutation handling. It returns no operation result. `:393` serializes writes, preserves no-replay behavior after uncertain writes, and reloads; `:459` silently ignores requests while busy. Expose explicit save progress/result and an edit-eligibility predicate rather than detecting success through shared status strings. An unconfirmed reorder blocks all playlist edits (`:394`), which also needs an explanatory disabled state.
- `Sources/MaroCore/YouTubePlaylists.swift:62` lists all pages of the account's `mine=true` playlists. `YouTubePlaylist` (`:3`) has no writable/collaborator capability. Current feasible scope is all listed own playlists; “any writable playlist,” if intended to include shared/collaborative playlists, is a separate discovery/permission feature.
- `Sources/MaroCore/YouTubePlaylists.swift:128` already checks all playlist-item pages for matching resource video ID and rejects duplicates; it also rejects concurrent additions of the same video/destination. Do not replace this with `loadedItemsByPlaylist`: that recommendation cache is capped at 50 items per playlist and 12 playlists (`PlaylistLibrary.swift:413`). Existing occurrences/duplicates remain intact.

## Proposed reusable control

Introduce a small `SaveDestinationButton` / popover content view accepting explicit video identity, optional source playlist ID, observed library/player state, and presentation style. Use `AppIconButton` (`Sources/MaroApp/AppDesign.swift:78`, 38-point target, tooltip/accessibility label) and native SwiftUI button-anchored popover presentation. There is no existing `.popover` or `NSPopover` implementation in `Sources/MaroApp`; existing primitives are Home `Menu`, the sheet above, and `PlaylistActionsSheet`.

Home uses icon-only `plus`, visible when the card is hovered **or the control has keyboard focus or its popover is open**. Keep it reachable by keyboard and assistive technology while visually quiet; hiding/removing the button from the hierarchy would prevent focus discovery. Label it “Save [title]”; show a focus ring, permit keyboard activation, Escape/outside-click dismissal, and restore focus to the invoking button. Reuse focus-return practice from `PlaylistDetailView.swift:109` and hover-or-focus visuals from `:224`/`:246`. Observe `PlayerPresentation` directly so saved state follows playback-independent Favorites changes.

Popover has Favorites first, then a scrollable full list of eligible playlists (no Home shortcut `prefix(7)` limit). Favorite membership can show a checkmark; preserve existing add/remove toggle and 20-item capacity unless the reviewed product decision changes this. Playlist rows are explicit add actions, not membership checkboxes: full membership/removal state is not available. Capture video ID and account scope for the invocation; dismiss or invalidate when route, source card, or account changes. Home remains mounted while hidden (`AppShellView.swift:18`), so do not rely only on disappearance.

The user clarified that saving belongs only to individual tracks. Share destination content/state with individual playlist-track controls, each bound directly to its video. The playlist toolbar retains play, existing actions and search, with no plus/save action. Row actions already save an explicit video and exclude their source playlist (`PlaylistActionsSheet.swift:14,49–59`), making them a direct reuse candidate. Bulk saving, playlist bookmarks and a new track-selection mode are outside this scope.

## Required behavior / acceptance criteria

1. Resting Home cards have no Save text; hover reveals one plus at card bottom-right. Focus and open-popover visibility are accessibility exceptions. Existing playback remains a distinct action and layout does not shift.
2. Clicking plus opens a popover attached to that button; selecting a destination never starts playback, changes route/queue, or opens the old sheet. Popover positioning works near window/scroll edges and long lists remain usable.
3. Favorites works disconnected; existing Favorites can be removed at capacity. Unsaved Favorites at 20 show a clear disabled reason. Playlist area distinguishes disconnected, initial loading, empty account, stale list, and write unavailable. Keep a path to the existing account/create flow without adding a new account setup UI.
4. A playlist click issues at most one write; other playlist actions are disabled during the existing global busy state. Show progress, destination-specific success, “already in playlist,” actionable failure, and confirmed-write/refresh-failed outcomes. Never automatically repeat an uncertain write. Preserve visible feedback if dismissal is permitted during work.
5. Deleted/changed destinations and disconnect/account switches cannot trigger a save against stale captured state. Recheck eligibility at submission. Do not falsely mark success when the existing guard silently returns.
6. Favorites state is authoritative local state; playlist membership is unknown until validated by API. Do not present every unchecked playlist as known absence or support unchecked removal without a separate complete-membership design.
7. Keyboard-only and VoiceOver users can discover plus, open it, identify destinations/state, activate, cancel, and return to the original card; hidden Home does not retain an active popover.
